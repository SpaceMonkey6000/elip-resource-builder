Phase 5 · scale

System design: architect for the predictable bottlenecks.

Every scaling story is the same four walls. Know the wall, know the fix.

📚
270k★ · WRITTEN REFERENCE

System Design Primer ↗

The definitive open-source library: CAP theorem, CDNs, L4/L7 load balancing, replication & sharding, plus Anki flashcards.
🎨
VISUAL

ByteByteGo / Alex Xu ↗

Free newsletter & YouTube breakdowns of real architectures (YouTube, URL shortener, notifications). Fastest way to build design vocabulary.

🧱 Too many users

Servers hit RPS limits → load balancers across replicated stateless app servers.

💾 Too much data

Vertical scaling fails → database sharding by a logical key (e.g. user_id).

🐌 High latency

Heavy writes exceed 500ms → async processing with message queues (Kafka, RabbitMQ).

🔀 Inconsistent state

Replication causes stale reads → design for eventual vs strong consistency trade-offs.

The engineering resume

Measure the engine. Then survive the 6-second scan.

The universal Resume Playbook covers ATS mechanics and the XYZ formula. Here's what's specific to engineers.

Keywords engineers must mirror exactly

THE ATS DOESN'T DO SYNONYMS

React.js (not ReactJS)Kubernetes (not k8s)JavaScript (not JS)CI/CDREST APIsPostgreSQLDockergRPCAmazon Web Services (AWS)

Include both the acronym and the full term, and keep an explicit comma-separated Skills section — the parser weights it heavily.

🧱

LaTeX is your friend. It enforces single-column structure and produces mathematically flawless text encoding — every character machine-readable. Jake's Resume & FAANGPath are the standards.
